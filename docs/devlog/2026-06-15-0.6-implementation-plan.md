## §C `rbcp-digest` 数据形状（M6c · Render/CLI 的消费契约，最关键的缝）

```python
@dataclass(frozen=True)
class SourceRef:               # 可追溯（可选填）：回原文出处
    kind: str                  # "char" | "timestamp" | "image"
    start: int | None = None   # 原文字符 offset
    end: int | None = None
    seconds: float | None = None   # 视频时间戳
    image_index: int | None = None # 图文第几张

@dataclass(frozen=True)
class Highlight:
    span_start: int; span_end: int    # 原文字符区间
    weight: float                     # 0-1，排序/"只看高亮"阈值

@dataclass(frozen=True)
class Card:
    quote: str
    source: SourceRef | None = None

@dataclass(frozen=True)
class OutlineNode:
    title: str
    source: SourceRef | None = None
    children: tuple["OutlineNode", ...] = ()

@dataclass(frozen=True)
class DigestResult:
    highlights: tuple[Highlight, ...]
    cards: tuple[Card, ...]
    outline: tuple[OutlineNode, ...]
    model: str

def digest(text: str, *, provider,
           segments: list[Segment] | None = None) -> DigestResult: ...
    # 调 LLM（OpenAI 兼容，provider 同 extract 那套）产出三形态。
    # 高亮/金句/脉络的定位是【确定性服务端锚定】，不是 LLM 报位置（见下）。
```

**高亮锚定（eng-review 定）**：**LLM 不返回字符 offset（它数不准、会标错位）**。LLM 返回"要高亮/金句的原话短语（verbatim 子串）"→ 后端 `str.find` 精确定位出 `span_start/span_end`；脉络/金句 `SourceRef` 同理后端锚定到字符 offset / 最近 `segment` 时间戳。原话在原文多次出现→全标、同 weight；LLM 改写致找不到→丢弃（或模糊匹配）。**因为锚定是确定性服务端步骤，"可追溯"几乎免费 → 砍掉 `with_trace` 开关，一直锚。**

**这是 Render（Desktop）和 CLI `digest` 共同消费的契约——锁死它，三形态 UI 和 `rbcp digest --json` 才能并行做。**

# 0.6 桌面端全功能建成并跑起来（Phase 1 后端 + Phase 3 前端 + Phase 2 Tauri）

> 一句话：桌面 App 从"残废速览查看器 spike"改造成**常驻 `rbcp serve` + 原生红蓝前端**的全功能桌面端，**端到端建成、`cargo tauri dev` 能启动**。进程级/集成级/生命周期级全验过；**唯一未验 = webview 里 6 屏的真实渲染（GUI），留白天人工 e2e**。
> 一晚 17 个线性提交（23:03→01:15，约 2h12m 构建；含 codex 探活+spike 全程约 3h）。

## 做了什么

三段，按依赖串：

### Phase 1 后端（8 任务，主仓库串行——routes.py 是咽喉文件，6 个任务都碰它，不能并行）
- 1.0 转录产物 canonical/segments 落 App 缓存（platformdirs，**非** ~/transcript，守红线#5）——速览数据地基
- 1.2 `/api/*` 收进 `APIRouter` + token 鉴权（`_ACTIVE_TOKEN=None` 放行兼容 WebUI/测试）
- 1.1 serve 桌面模式（`_build_serve_config`：127.0.0.1+port0；`_DesktopServer` startup 后回吐 `{port,token}`）
- 1.3 `GET /api/jobs/{id}/digest`（两层信封同 CLI `--json`，读 artifacts→重建 Segment→digest()→落缓存；缺 artifacts→409）
- 1.4 批量成功也 `on_job_success`（批量 job 速览可用）。**eager 预生成 digest 砍掉**，走 1.3 端点 lazy（省 LLM 成本）
- 1.5 桌面模式禁 pydoll 端点（`RBCP_DESKTOP=1`→`/uploaders/posts`、`/comments` 404）
- 1.6 单篇删除 `DELETE /api/jobs/{id}`（删 md+缓存，**走 job_id 不传 path**，含路径穿越红线测试）
- 1.7 `/api/stats` 增 `by_stage`（按环节聚合 cost+时长；**无 TTFT**）
- 补：`readable_text` 贯通（阅读器②清洗全文数据源）；桌面模式放宽 CORS

### Phase 3 前端（地基锁接缝 → 6 屏 codex 真并行）
- 地基：`index.html`（sidebar + 5 `.screen` 挂载点 + `#modal`/`#compose-mount`）+ `styles.css`（红蓝设计系统）+ `app.js`（nav 路由 + `window.rbcpOpenReader` 跨屏契约）+ `api.js`（12 端点客户端，base/token 可配）+ `lib/`（highlight 码点切片/notes 校验/errors 分层，15 单测）
- 6 屏（各自独立模块，**6 个 codex 同时写**）：jobs（2s 轮询+重试+开阅读器）/ library（搜索/排序/筛选/双模式/删除/复制）/ reader（倒三角三形态，①canonical 高亮走 lib/highlight.js）/ usage（by_stage 账单）/ settings（localStorage）/ compose（单篇+批量 notes.json 导入）

### Phase 2 Tauri 壳（我直接写 Rust——codex 没联网、Tauri v2 版本特定 API 风险高）
- `lib.rs`：spawn 常驻 `rbcp-serve` sidecar，阻塞读 stdout `{port,token}`（20s 超时）存 State；`get_api_config` 命令暴露给前端；后台 drain stderr；`ExitRequested` 时 kill child；single-instance（二次启动聚焦旧窗不起第二个 serve）
- `serve_entry.py`：sidecar 跑桌面 serve（`RBCP_DESKTOP=1`→CORS+禁pydoll、`new_token`、`_DesktopServer` 回吐 port/token）+ **父进程 watchdog**（修 onefile 孤儿泄漏）
- `build.sh`：PyInstaller **onefile** 打 rbcp-serve（19M，项目全依赖 + uvicorn 4 hidden-import + templates + 排除 pydoll）
- 传输决策：**CORS + 普通 fetch**（非 plugin-http）——serve 绑回环+token 兜底所以 CORS `*` 安全；好处是前端在浏览器 dev 也能调（同一套代码）

## codex@MiMo-UltraSpeed 并行编排教训（可复用）

这次大规模用本地高速 codex（mimo-v2.5-pro-ultraspeed，1000 TPS）并行执行，沉淀几条：
- **codex 稳定做对"实现+定向测试"，但常在"全量验证+git commit"前停**（effort 高低都一样，token 预算到了模型自己收尾）→ 定型分工：**codex 写代码+测试，我（主控）跑全量验证+提交**（验证本就该是主控的活）。
- **跨多文件任务 codex 常漏 routes.py 的 HTTP 路由那一环**（storage/缓存层做对，路由忘了）→ 拆细 or 预期补一刀续做包。
- **禁 `sed`/批量正则改文件**：codex 用 sed 把 pipeline.py 改乱过；stub 里的全角中文让 apply_patch 匹配失败 → 让它"整文件覆盖"。
- **并行解法**：codex 反正不自己 commit → 在同一主仓库并发跑**碰不相交文件**的 N 个 codex，最后我统一提交。避开 worktree 的 venv 漂移（worktree `uv sync` 拉到不同 fastapi 版本坑过）+ 并发 git 锁（`.git/index.lock` 残留坑过）。
- **接缝先锁再 fan out**：先串行建地基把 api.js 契约+各屏模块接口锁死，再 6 屏并行——不锁接缝并行=各自分叉。
- **喂 codex 前主控先 grep 核实事实**（函数签名/字段名/类型坑，如"缓存 segments 是 list[dict] 但 digest() 要 tuple[Segment]"），否则它照着错的实现。
- **Rust/Tauri 这种 codex 没联网+版本特定的，主控直接写**（CSP/plugin/capabilities 版本敏感，喂事实不如自己写准）。

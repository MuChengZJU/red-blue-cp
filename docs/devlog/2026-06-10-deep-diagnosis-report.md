# 产品与技术深度诊断报告（实证版）

> 对 0.5.2 全量代码、插件、文档体系、外部数据做的一轮系统调查，
> 为 [方向盘点](2026-06-10-product-tech-diagnosis.md)（讨论稿）补实证地基。
> 调查方式：4 路并行审计（主程序红线合规 / 浏览器插件 / 文档一致性 / GitHub+PyPI 外部数据）+ 全量测试实跑 + 关键发现人工复核。

## 总体结论（TL;DR）

1. **技术地基是健康的**：13 条红线全部合规（逐条有 file:line 证据）、484 测试全过、三层纪律守住、错误处理成熟。继续往上盖楼是安全的。
2. **产品处于「作者自用成立、外部用户≈0」阶段**：确凿的外部真实用户 1 个（GitHub 用户 LilJay-H，提了带测试的 Draft PR #46）、弱信号约 10 个（star/访客）、0 issue。PyPI 下载量峰值全部对齐发版日，大头是机器人。
3. **最大的产品硬伤是新用户首跑路径断裂**（本次最重要发现）：README/SPEC 承诺的 `~/.config/rbcp/.env` 配置路径**代码从未实现**——这是 2026-05-09 工程评审第 10 条决议，决议定了、文档照写了、实现漏了。从 PyPI 装包的陌生人照 README 走必然卡死在配置这一步。
4. **唯一的外部真实需求信号指向 PLAN 待办区**：PR #46 做的正是「provider env 化」——待办区写着「等真实需求出现再做」，**真实需求现在出现了**。
5. 竞品格局确认：「B站+小红书双平台 + 原文级转录 + 本地 Markdown」组合仍是空白；但 BiliNote（6.3k star）已占住「B站视频→AI 笔记」单平台心智。同量级相邻项目全部建完即停更，持续迭代本身是相对优势。

### 1.2 新用户首跑路径断裂（🔴 实现缺口，非纯文档问题）

复核确认的事实链：

1. `README.md:62` 教用户：`mkdir -p ~/.config/rbcp && cp .env.example ~/.config/rbcp/.env`；
2. pipx/uv tool 装的 PyPI 包里**没有** `.env.example`（只在源码仓库）；
3. `app/cli.py` 全部 6 处 + `app/web/routes.py` 1 处的 `load_dotenv()` 均为**无参调用**——只从当前目录向上找 `.env`，永远不读 `~/.config/rbcp/.env`；
4. 源头：2026-05-09 Eng Review R1 第 10 条决议「配置发现顺序：环境变量 > `~/.config/rbcp/.env` > 当前目录 `.env`」从未落地，SPEC/README 都按决议写了。

作者自己没踩到，因为始终在源码目录跑（当前目录有 `.env`）。**陌生人从 PyPI 装包后第一步就走不通**——这意味着现有的 star/下载几乎不可能转化成用户，发再多功能也漏在漏斗第一格。附带缺口：README 未说明 ffmpeg 是前置依赖（音视频转录必需）。

注意一个 pattern（不止这一处）：**「决议/文档先行、实现没跟上、且没人从 PyPI 包视角做过新用户路径实测」**。PR #46 撞上的也是同类问题（文档承诺的配置不生效）。0.5.2 的真链路验收一直是作者视角（源码目录 + 已配好的 .env），缺一个「干净机器 + pipx 装包」的验收视角。

## 二、技术诊断

### 2.1 主程序：红线 13/13 全合规，整体评级 A

逐条审计结果（摘要，全部有 file:line 证据）：

- 文件访问全走 job_id，无任意路径接口，路径穿越有显式测试（`tests/test_routes.py:305`）；
- Markdown 原子写（`.tmp` + `os.replace`，失败清理）；失败任务三件套（status/error_message/log_excerpt）落库且 WebUI 可见；
- 媒体只在 tempfile / 独立 `RBCP_MEDIA_DIR`，知识库目录干净；`serve` 硬写 `workers=1`；
- 依赖 = 白名单 8 个，零偷加；pydoll 懒加载（只在壳层函数内 import）；
- 异常处理成熟：30 处 `except Exception` 全部有 noqa 注释 + 日志 + 不吞异常；外部 API 失败全部打印 response body 摘要；
- 零 TODO/FIXME/HACK 残留。

### 2.2 主程序技术债（按「加新功能时谁先痛」排序）

| # | 债 | 证据 | 何时会痛 |
|---|---|---|---|
| 1 | `discover.py` 724 行（解析+浏览器壳+cookie+工具混一文件） | 超 300 行规范 141% | 加新抓取源（如收藏夹同步）时 |
| 2 | `model.py` 630 行（ASR 管道/OSS 上传/SSE 解析/手写 multipart 全在内） | 单函数最长 70 行 | 加 provider（PR #46 正撞上）时 |
| 3 | `storage.py` 578 行 + 无正式迁移机制（靠 IF NOT EXISTS 风格手工迁移） | schema 改动无 migration 框架 | 任何加表/加列的功能（MCP 出口、收藏夹都要） |
| 4 | `fetcher.py` 518 行，字段解析靠 `_first_present()` 多名兼容兜底 | fetcher.py:149-152 | 平台改接口时（静默 default，无告警） |
| 5 | batch 参数长链传递（routes→run_batch 七八个裸参数） | routes.py:334-342 | 改批量工作流时 |

均不紧急，但 1-3 与方向盘点里的候选方向（MCP 出口、收藏夹同步）直接相关——**立项前先拆对应文件比立项后边加边拆便宜**。

### 2.3 浏览器插件（0.3.1）：功能成立，维护模式有结构性问题

- **双份手工副本**：油猴脚本（330 行）与 MV3 主世界脚本（223 行）约 80% 逻辑重复，无构建工具、改一处要手工同步两处；
- **零 JS 测试**：Python 侧 484 测试，JS 侧 0，全靠真博主手测；
- **失败静默**：多处 `catch(e) {}` 无声吞掉（如 `main-world-hook.js:205-207` JSON 解析失败无任何提示）——小红书改接口时用户只会看到「导出为空」，无诊断线索；
- **最脆两点**：`user_posted` 字符串匹配（接口改名即失效）、`__INITIAL_STATE__.user.notes` 硬编码路径（Vue 结构变即失效）；
- CHANGELOG 漏记 0.3.1（manifest 和脚本头都是 0.3.1，CHANGELOG 停在 0.3.0）；
- `@updateURL` 自动更新链路有效（指向 GitHub raw main 分支）。

判断：当前可用、短期无虞；但**小红书一次接口变更会同时打穿两份副本且无测试网兜底**，届时是双倍修复成本。插件再要加功能（如收藏夹拦截）前，先抽公共核心。

### 2.4 测试体系

- 484 全过，1.28 秒跑完 → 全 mock，不打真实 API（设计如此）；
- 关键安全场景有显式测试（路径穿越/失败持久化/原子写/去重）；
- 真链路验证靠人工 QA 纪律（CLAUDE.md 已规定里程碑收尾必实测）——缺口在 §1.2 所述「干净机器装包」视角；
- 一个低优先警告：FastAPI `on_event` 已弃用（routes.py:153），下次大版本升级 FastAPI 时要换 lifespan。

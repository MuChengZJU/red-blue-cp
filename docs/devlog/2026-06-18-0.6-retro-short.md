# 0.6 周期短反思（详细版后补）

> 这是简版，趁记忆新鲜先记骨架；详细复盘（含各阶段 metrics、AI 协作方法论对照）后续单独写。

## 一句话

0.6 把产品从「忠实原文」推到「帮人快速读懂」，引擎层（Extract/Digest 分层 + 确定性锚定）建得很稳，**痛点全在桌面端这层新形态**——既是新技术栈（Tauri + 冻结 sidecar），又是用户最在意、最能看见的那一面。

## 做对的

- **契约先行 + 分层隔离**：Extract（无损）/ Digest（有损 LLM）物理隔离、确定性服务端锚定，让"AI 提炼"可控可验证，没有变成糊在一起的黑盒。
- **workflow 编排成了常态**：understand（并行调研锁契约）→ implement → review（多维度 × 对抗验证）三段式，在引擎和桌面补强上都用上了，确实抓住了单测兜不住的集成契约 bug。
- **真链路实测当门**：每轮都打到外部 API、用真数据，没被"测试全绿"骗过。

## 痛 / 踩的坑

- **桌面端被低估**：一开始当"速览查看器 spike"压成最薄，结果用户视角=残废。教训已记（按"用户价值可见度"分配投入，不只按技术难度）。本周基本是在还这笔债。
- **冻结 sidecar 的调试盲点**：改源码不重打不生效，连环误判过两次。桌面端 = 前端（重载）+ 后端（重打），调试要先分清改的哪层。
- **`getenv(k, default)` 空串雷**：设置页能存空串 + 读侧默认值不兜空串 = 反复踩。
- **迭代靠用户真机逐轮暴露**：好处是问题真实，代价是节奏被打断、来回多。下次新形态上线前自己先把"用户视角全链路"走一遍。

## 给下一阶段（Cloud/计费/Mobile）的提醒

- 新形态（手机端/云端）别再压成 spike——上线前按用户可见度补够。
- 计费/云涉及钱和多租户，契约和边界要比本地版更早锁死、更严验。
- 双前端漂移的账（WebUI vs 桌面）别再开第三份；能收敛就收敛。

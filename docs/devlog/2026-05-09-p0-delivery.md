## 理由

### 为什么用 TDD + Codex 并行

- TDD 让我（CC）通过测试精确定义接口契约，Codex 实现时不需要猜
- 并行调度 Codex 把"等编译"时间压到接近零（后台跑时我可以写下一批测试）
- 每模块独立 commit，回滚成本可控

实测下来，10 多轮 Codex 调度只有 1 次需要重写（model.py 的 ASR mock 结构跟我设计的不太一样，但调整测试就过了）。

### 为什么 P0 不抽 PlatformAdapter / Pipeline

CLAUDE.md 红线：P0 反过度抽象。`if/elif platform == 'bilibili':` 三行 dispatch 就够了，强行抽象层会让代码量翻倍且没增加灵活性。

Eng review R2 也确认这条。

# 产品与技术诊断：0.5.2 之后往哪走（讨论稿，未拍板）

> v0.5.2 全部里程碑交付后的方向盘点：6 个候选方向 + 讨论中冒出的 2 个新方向，
> 按「产品价值 × 技术可行性」逐项诊断，给出三条路线方案。**本文是分析报告，决策未锁定。**

## 背景

0.5.2 发布（PyPI + 插件 0.3.1 油猴分发），无进行中里程碑。作者提出 6 个候选方向：

1. MLM（多模态大模型，如 Qwen、Gemini Flash）替代专用 ASR
2. WebUI 配置向导（降低非技术用户安装门槛）
3. 自部署服务的远程访问（局域网外可达）
4. 桌面客户端
5. 公开体验服务 / 收费 SaaS
6. 知识库管理（自用）

讨论中又冒出 2 个新方向：

7. **收藏夹自动转录**（B 站收藏夹 / 小红书收藏自动同步进知识库）
8. **MCP / Agent Skill 出口**（转录结果直接被 Claude 等 AI 消费，省掉手动粘贴）

## 现状诊断：dogfood 实证

上一轮（2026-06-04 office hours）定的 dogfood 优先已有结论——**核心 loop 跑通了**：

- 作者每天在用：看到好帖子（B 站视频 / 小红书图文视频）→ 复制 URL → WebUI 转录 → 复制 Markdown → 粘贴给 Claude 网页版对话消化。
- 体验评价「用着挺好」。说明转录质量、稳定性、知识库落盘这套地基是成立的。
- **残留摩擦恰好是 loop 两端的手动步骤**：
  - 输入侧：逐条手动复制 URL（看到「收藏夹自动转录」类项目后觉得更方便，触发方向 7）
  - 输出侧：逐条手动粘贴给 Claude（触发方向 8）
- 知识库整理类工作流（Karpathy 式个人知识库）尚未搭起来——输出侧需求还在萌芽期。

## 消费端矩阵（讨论中确立的框架）

每种产品形态对应一个消费平台，这是后续排优先级的坐标系：

| 形态 | 消费端 | 现状 |
|---|---|---|
| WebUI 手动粘贴 | Claude 网页版 | ✅ 每天在用（现行 loop） |
| MCP server | Claude 网页版 / Desktop（自动化） | ❌ 未做 |
| CLI + Agent Skill | Claude Code / Codex / 自部署 Agent | 🟡 CLI 已有，作者本机已写 rbcp skill，未正式分发 |
| 文件落盘 | Obsidian 等本地工具 | 🟡 天然可用（`RBCP_OUTPUT_DIR` 指向 vault 即可），无专门支持 |
| 桌面 GUI | 非技术桌面用户 | ❌ P2 门控（2026-06-03 定） |
| 公开 Web | SaaS 用户 | ❌ 搁置（2026-06-04 定） |

## 外部 landscape（2026-06-09 检索）

- **B 站 MCP server 已有多个**（bilibili-video-info-mcp 等）：能抓字幕/弹幕/评论，但只覆盖 B 站、只拿平台字幕（无 ASR 兜底）、不做小红书、不持久化 Markdown。
- **知识库类 MCP 是最大品类**（“Knowledge & Memory” 280+ servers），「本地文件暴露给 AI 读」模式成熟，有现成范式可抄。
- **「收藏夹自动转录成本地 Markdown」没有找到现成开源方案**——现有工具都是手动输入 URL；BibiGPT 是商业 SaaS 且不落地本地文件。
- 结合既有竞品认知（得到大脑：封闭第二大脑，覆盖面广但数据不可移植）：rbcp 的差异点依旧是**开源 + 原文忠实 Markdown + 数据自有**，而「B 站+小红书收藏夹 → 本地知识库」组合目前是空白。

## 八个方向逐项诊断

| # | 方向 | 产品价值 | 技术可行性 / 成本 | 诊断 |
|---|---|---|---|---|
| 7 | 收藏夹自动转录 | 🔴 高——消除输入侧手动步骤，「收藏即入库」；市场空白 | B 站公开收藏夹有 Web API（待 spike 验证）；小红书收藏需调研（公开收藏页或插件拦截）；增量 2-3 天 | **新输入模式，建议优先**。先做 B 站（API 稳），小红书后补 |

| 2 | WebUI 配置向导 | 🟡 中——非技术用户装机门槛真实存在 | 首启检测无 Key → `/setup` 页 → 填 Key 测连通 → 写配置文件；≈1 天 | 价值成立但受众（非技术用户）还没真实出现，与桌面 GUI 同属「给别人用」线 |
| 3 | 远程访问 | 🟡 中——自用刚需（不在部署机旁就用不了） | Tailscale 私有网零代码（PLAN Q1 已定为首选）；公网中转方案撞鉴权红线 | 按既有决议执行即可，**是配置动作不是开发项目**。注意：若未来做 remote MCP，与此处基建天然耦合 |

| 4 | 桌面客户端 | 🟢 低（当前） | Tauri 打包/签名/自动更新是独立第二条分发线，贵 | 维持 P2 门控（真实非技术用户 + Key 上手路径，两条缺一不做）。配置向导(2)是它的前置 |

## 三条路线方案

### 路线 A：闭环优先（建议）

**MCP 本地档 + Agent Skill（≈2 天）→ B 站收藏夹同步 spike + 实现（≈2-3 天）。**

- 直接消除核心 loop 仅剩的两个手动步骤，自动化的是**已被每日使用验证的行为**，不是猜想。
- 收藏夹同步是检索确认的市场空白，且 rbcp 已有最难的部分（双平台 + ASR + VLM + 持久化），别人从零追要重建整条流水线。
- 风险：小红书收藏接口形态未知（先只做 B 站规避）；MCP 仅覆盖 Claude 生态（但作者消费端就是 Claude，匹配）。

### 路线 B：自用基建优先

**Tailscale 远程（0.5 天，配置动作）→ 配置向导（1 天）→ MLM spike（1 天）。**

- 每步小且确定、无技术风险；但**不改变核心 loop**，做完后日常使用方式不变。
- 适合作为路线 A 的间隙填充，不适合作主线。

### 路线 C：全栈消费端铺开

MCP + Skill + Obsidian 指引 + 远程 + 配置向导一轮做完。

- 覆盖广但精力分散，正是 2026-06-04 上一轮已经否决过的「全形态都做」反模式。不建议。

**建议：A 为主线，B 里的 Tailscale 作为零代码配置动作随时可做，MLM spike 与收藏夹 spike 可并行塞缝隙。4/5/6 维持既有门控/搁置决议不动。**

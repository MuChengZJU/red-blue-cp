# 复盘 · WebUI 重做：设计一次过，但「真链路实测」是假的

> 这次 WebUI 从零重做，设计方向一次过（用户「不错不错 好看 就这样」）。但过程暴露一个真问题：我两次说「done，已实测」，都被用户上真实数据后当场打脸——因为我拿自己捏造、且丢了真实数据关键特征的合成数据做验证。合成数据的「通过」给了虚假确定性，比没测更危险。

## 背景

任务：把 P0 的 WebUI 从零重做成「红蓝品牌」设计 + Markdown 渲染/源码切换。流程顺：`/design-consultation` 出 4 个方向的 GPT Image 提示词 → 用户选方案 3 → 实现 3 模板 + 测试 → 自测 → commit。最终设计本身一次过。

但「完工」这关，我连续两轮判断失误，都是被用户逼着上真实数据 / 全面 QA 才暴露 bug。

## 现象：两轮假「done」

**第一轮**：我用手写的 `sample.md` 截图自测，截图很漂亮，说「全链路跑通了」。
→ 用户上真实库，**详情页 frontmatter 被渲成巨大标题**的 bug 当场出现。
根因：真实 md **每个都带 YAML frontmatter**，marked 把「一行文字紧跟 `---`」当 setext 二级标题，整块元信息（含超长 URL）渲成巨标题。**我手写的测试 md 恰好没 frontmatter——丢了那个会触发 bug 的关键特征。**

**同一轮的「秒表不准」**：我 seed 的 running 任务卡在 `mark_running` 那一刻不动，计时显示「距 seed 多久」，看着乱跳。我还跑去查时区/微秒解析。**根因还是假数据**，计时逻辑本身是对的（受控实测 `0:01→0:05` 准确）。同一个坑一次会话咬两次。

**第二轮**：修完上面两个，我又说「done」。用户让我「全面测试 UIUX」，我用浏览器自动化打真实库，又挖出 4 个 bug，其中一个还是我自己埋的（`.toolbar{display:flex}` 静默盖掉 `[hidden]` 的 `display:none`，工具栏没真隐藏）。

## 根因

**第一轮的两个问题是同一个病：我拿自己捏造的数据验证，而捏造的数据丢了真实数据的结构特征。**

- 比「没测」更糟：没测我知道自己没把握；**假测给了虚假的确定性**，于是我敢说「done，看截图」。
- 两轮 QA 实际上是**用户替我做的**——他逼我上真实数据、逼我全面测，bug 才出来。

这条和 [接线层 bug 复盘](2026-05-09-integration-layer-bugs.md) 是邻居但更进一步：那次是「架构审 + 单测抓不到接线 bug，要 e2e」；**这次我连 e2e 都做了，只是喂的数据是假的**——所以"做了 e2e"不等于"验证有效"。

## 教训（可复用）

1. **合成/seed 测试数据必须保留真实数据的结构特征**（frontmatter、真实时间戳、真实长度的脏 URL、特殊字符…），否则它给的「通过」是负价值。
2. **凡是消费用户真实数据的功能（读 md、读 DB 行），"完工"那一关至少打一个真实样本**。seed 数据可以测广度，但 done 的门槛要有 ≥1 个真实工件。
3. 推论：**"做了端到端测试" ≠ "验证有效"**。要追问喂进去的数据像不像真的。
4. （工程细节，已记 [功能 devlog](2026-06-03-webui-redesign-and-qa.md)）`[hidden]` 会被 `display:flex` 静默盖掉；改 `routes.py` 必须重启 uvicorn（模板热重载、Python 模块不重载）；worktree 里 Write 别用主仓库硬编码绝对路径。

## 做对的（别只记教训）

- 设计一次过：`/design-consultation` 出多方向提示词让用户选，品牌色（红=小红书/蓝=B站）从装饰变功能标识。
- 守住红线：marked+DOMPurify 走 CDN 非 Python 依赖；爬来的内容渲染前强制清洗防 XSS。
- 每修一个 bug 补一条回归测试（21→24，全量 264 过）。
- 浏览器自动化 QA 确实挖出了单测抓不到的 bug——工具是对的，只是该早一轮、且喂真实数据。

## 后续 / 改进

- 个人验证纪律：说「done」前自问一句「喂的是真实数据还是 seed？真实数据的关键特征都在吗？」
- 给用户的协作杠杆：我说 done 时，可直接追问「真实数据测的还是 seed 的」，大概率能逼出没测干净的地方。
- 已沉淀 memory：`synthetic-data-must-match-real`（跨会话生效）。
